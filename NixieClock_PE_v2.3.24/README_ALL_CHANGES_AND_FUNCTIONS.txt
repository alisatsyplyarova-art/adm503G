1. УПРАВЛЕНИЕ КНОПКАМИ (кратко, в режиме часов)
================================================================
- "минус" (кратко)     - переключает режимы подсветки по кругу (0-5),
                          номер режима на 2 сек показывается на
                          индикаторах.
- "минус" (удержание)  - вкл/выкл секундная точка.
- "плюс"  (кратко)     - переключает эффект перелистывания цифр
                          (всегда, независимо от режима подсветки).
- "плюс"  (удержание)  - действие зависит от текущего режима подсветки:
                            красный/синий/зелёный -> вкл/выкл "дыхание";
                            радуга                -> смена скорости
                                                      перехода (isHolded,
                                                      разово);
                            градиент              -> пока зажата, цвет
                                                      крутится по кругу
                                                      (isStep, непрерывно);
                            отключена              -> не действует.
- сенсор (кратко/удержание) - температура/давление/влажность/будильник,
                          возврат в часы. ПРИ SENSOR_MODE == 3 (без
                          датчика) эта кнопка НЕ переводит в показ
                          параметров вообще - см. раздел 8. Остановка
                          сигнала будильника работает всегда.
- М (двойной клик)     - настройка времени.
- М (удержание)        - настройка будильника.


================================================================
2. СЕКУНДНАЯ ТОЧКА (DOT_ALLOWED)
================================================================
Раньше на кнопке "минус" (удержание) был переключатель "глюков".
Теперь там - вкл/выкл секундной точки:
  DOT_ALLOWED = !DOT_ALLOWED;
Имеет приоритет во ВСЕХ режимах (кроме показа температуры, где точка -
десятичный разделитель и должна гореть всегда, независимо от настройки).
Сохраняется в EEPROM (DOTEFF), восстанавливается после перезапуска.


================================================================
3. ИНДИВИДУАЛЬНАЯ ЯРКОСТЬ ПОДСВЕТКИ ПО ЦВЕТАМ (день/ночь)
================================================================
Раньше была одна общая яркость на все 3 цвета. Теперь отдельно для
каждого канала, отдельно день/ночь:
  BACKL_BRIGHT_R/G/B       - дневная, по цветам
  BACKL_BRIGHT_N_R/G/B     - ночная, по цветам
Хранятся в массиве backlMaxBright[3] (индексы: 0-R, 1-G, 2-B, как в
backlColors[]).
Для "радуги" и "градиента" яркость ОБЩАЯ для всех цветов (не по
отдельности) - иначе цвета выглядели бы неравномерно ярко при переходе:
  BACKL_BRIGHT_RAINBOW / BACKL_BRIGHT_RAINBOW_N -> rainbowMaxBright


================================================================
4. СТАРТОВЫЙ АППАРАТНЫЙ ТЕСТ УСТРОЙСТВА (selftest.ino)
================================================================
Запускается ТОЛЬКО при включении с зажатой кнопкой "минус", только для
плат с NUMTUB == 6. Шаги:
  1. IN-14: все 6 ламп одновременно 0->9, по 1 сек на цифру.
  2. Каждая лампа отдельно (остальные погашены): 1->2...9->0, по
     0,3 сек на цифру.
  3. Неоновая точка - принудительно на 1 сек.
  4. RGB - по очереди R -> G -> B, по 1 сек на цвет.
  5. Питание (Vcc) - реальное напряжение платы через встроенный
     источник 1.1В (без ADC-канала), формат "5.00" на индикаторах 2,3,4
     + точка как разделитель, 3 сек.
  6. HV - расчётное напряжение + сырой ADC A6, например "170550"
     (170В / ADC 550), 3 сек.
  7. DC-DC - текущий PWM + статус защиты (000 NORMAL/111 WARNING/999
     FAULT, при FAULT дублируется миганием красным), 3 сек.
Тест не зависит от SENSOR_MODE - датчик в нём не участвует.


================================================================
5. ЗАЩИТА DC-DC (DCDC.ino) - три состояния
================================================================
Было: только вкл/выкл (dcdcFault, bool).
Стало: enum DCDC_STATE_T { DCDCST_NORMAL, DCDCST_WARNING, DCDCST_FAULT }
  - NORMAL  - всё в порядке, обычная регулировка.
  - WARNING - HV просело, но ещё в допустимых пределах (PWM >= 165,
              A6 < 450, дольше 2 сек) - генератор продолжает работать.
  - FAULT   - авария: перенапряжение (A6 >= 700, 100 мс) или затяжная
              просадка при большом PWM (PWM >= 175, A6 < 350, 5 сек).
              Генератор выключается (setPWM(GEN,0)) БЕЗ автоповторного
              запуска - выйти можно только перезапуском платы.
При FAULT подсветка мигает красным (независимо от выбранного режима
подсветки) - и в обычной работе часов, и в шаге DC-DC стартового теста.

ВАЖНО: показ вспомогательных чисел на индикаторах (номер режима/
эффекта, пресет скорости радуги, позиция градиента) реализован через
ГАШЕНИЕ лишних разрядов (anodeStates), а не через "0" на них. Резкое
изменение количества одновременно горящих ламп меняет нагрузку на
анодное напряжение и способно кратковременно поднять его, что защита
от перенапряжения может воспринять как аварию (ложный FAULT). Если это
будет происходить на практике - самый надёжный вариант: выводить "0" в
лишних разрядах вместо их гашения (все 6 ламп остаются включёнными
постоянно, нагрузка на HV не меняется скачком) - такой вариант уже
реализовывался в v2.3.15, при необходимости можно вернуться к нему.

6. РЕЖИМЫ ПОДСВЕТКИ (BACKL_MODE) - полная переработка
================================================================
Было (изначально): один общий цикл "дыхание с автосменой цвета /
постоянно / отключено", позже - 9 отдельных режимов (дыхание/постоянно
на каждый цвет по отдельности). В итоге остановились на 6 режимах:

  0 - BL_RED    - красный (постоянно или "дыхание", см. colorBreathing)
  1 - BL_BLUE   - синий   (то же)
  2 - BL_GREEN  - зелёный (то же)
  3 - BL_RAINBOW   - радуга: непрерывный кроссфейд одного цвета в
                     другой по кругу. Уходящий цвет гаснет, следующий
                     ОДНОВРЕМЕННО и с той же скоростью разгорается -
                     оба канала подсветки светятся всё время перехода
                     (без провала в темноту, без "вспышки"). Скорость -
                     6 пресетов (RAINBOW_TIME_PRESETS), листаются
                     удержанием "плюс".
  4 - BL_GRADIENT  - ручной выбор цвета: пока зажата "плюс", цвет
                     крутится по кругу градиента красный->зелёный->
                     синий->красный (isStep(), шаг GRADIENT_STEP каждые
                     GRADIENT_STEP_TIME мс). Позиция (gradientPos,
                     0-767) сохраняется в EEPROM при отпускании
                     (isRelease()).
  5 - BL_OFF       - подсветка выключена.

"Дыхание" (colorBreathing) - общий флаг для режимов 0/1/2, переключается
удержанием "плюс", сохраняется в EEPROM (BLBREATH).

При переключении режима кнопкой "минус" номер режима (1-6, с учётом +1
для отображения) на 2 сек показывается на индикаторах, затем время
возвращается НАПРЯМУЮ (без эффекта перелистывания цифр) - см.
forceDirectTime.

Прокрутка градиента изначально делалась через постоянный опрос
btnR.state() - оказалось ненадёжно на реальном железе (могло зависать
или запускаться само по себе). В итоге переведено на штатный механизм
самой библиотеки кнопок: btnR.isStep() (повтор при удержании) и
btnR.isRelease() (сохранение в EEPROM один раз при отпускании).


================================================================
7. НОВЫЕ ЭФФЕКТЫ СМЕНЫ ЦИФР (effects.ino)
================================================================
  FM_SLOT     - "барабаны игрового автомата" по очереди: только ОДИН
                разряд крутится за раз (слева направо), цифры идут по
                порядку (0,1,2...9,0...), точная остановка на нужном
                значении без скачка. Срабатывает раз в минуту.
  FM_SLOT_ALL - тот же принцип, но крутятся ВСЕ разряды одновременно
                (чем правее разряд, тем дольше крутится - отсюда
                разновременная остановка).
Секунды внутри минуты у обоих идут обычным порядком, без эффекта.


================================================================
8. ДАТЧИКИ ТЕМПЕРАТУРЫ/ВЛАЖНОСТИ/ДАВЛЕНИЯ (SENSOR_MODE)
================================================================
Выбор в главном файле:
  #define SENSOR_MODE 1

  0 - только AHT20 (температура + влажность, без давления)
  1 - AHT20 + BMP280 (температура + влажность + давление)
  2 - BME280 (температура + влажность + давление)
  3 - БЕЗ ДАТЧИКА (новое, добавлено в v2.3.17)

Компилируется только выбранный набор библиотек (Adafruit_BME280 /
Adafruit_BMP280 / Adafruit_AHTX0), чтобы уменьшить размер прошивки.

Унифицированные функции чтения (0_data.ino), не зависящие от типа
датчика:
  readSensorTemperature(float &temperature)
  readSensorHumidityInteger(int &h)
  readSensorPressureMMHg(int &pmm)
Каждая возвращает true/false (есть данные или нет) и сама разбирается,
какой физический датчик опрашивать в зависимости от SENSOR_MODE.

SENSOR_MODE == 3 ("без датчика"), подробности:
  - Ни одна библиотека датчиков не подключается (#include пропущены).
  - В setup() инициализация датчика полностью пропускается.
  - Все три функции чтения выше сразу возвращают false/NAN, ни разу не
    обращаясь к шине I2C.
  - Обработчик кнопки "сенсор" в режиме часов (переход в показ
    температуры) обёрнут в #if SENSOR_MODE != 3 и при этом варианте
    ВООБЩЕ ОТСУТСТВУЕТ - короткое нажатие и удержание в режиме часов
    ни на что не влияют.
  - Остановка сигнала будильника той же кнопкой продолжает работать -
    это отдельная, не зависящая от датчика функция (обрабатывается в
    самом начале buttonsTick(), до проверки SENSOR_MODE).
  - Экраны SHTEMP/SHATM/SHHUM физически недостижимы (нет входа в них),
    сам код этих экранов в файле остаётся, но никогда не выполняется.

Калибровочная поправка температуры (TEMP_CORRECTION) применяется
одинаково для всех вариантов датчика, кроме SENSOR_MODE == 3 (там
поправку применять не к чему).


================================================================
9. ПРОЧИЕ ИСПРАВЛЕНИЯ БАГОВ
================================================================
- isFreeze (заморозка автопрокрутки температуры/давления/влажности)
  теперь сбрасывается при возврате в часы (retToTime()) - раньше могла
  "залипать" при повторном заходе в эти экраны.
- flipInit сбрасывается при смене эффекта цифр кнопкой - раньше новый
  эффект мог унаследовать состояние предыдущего и не обновлять цифры
  до следующей смены минуты.
- BACKLG/BACKLB (пины зелёного/синего подсветки) были перепутаны -
  переставлены местами.
- GLITCH_ENABLED = 0 в главном файле - эффект "глюков" полностью
  отключён (компилятор выкидывает код), независимо от кнопок/EEPROM.

10. ПОЛНЫЙ СПИСОК ФУНКЦИЙ ПРОЕКТА С ПОЯСНЕНИЯМИ
================================================================
(только новые или существенно изменённые; штатные функции базовой
прошивки, которые не менялись, здесь не описаны)

--- 0_data.ino ---
bool readSensorTemperature(float &temperature)
bool readSensorHumidityInteger(int &h)
bool readSensorPressureMMHg(int &pmm)
  Унифицированное чтение датчика независимо от SENSOR_MODE (0/1/2) или
  его отсутствия (3) - см. раздел 8.

--- bright.ino ---
byte modeColorIndex(byte mode)
  Возвращает индекс канала подсветки (0-R,1-G,2-B) для текущего
  цветного режима (BL_RED/BL_BLUE/BL_GREEN).

void applyGradientColor()
  Вычисляет RGB по текущей позиции gradientPos (0-767, 3 сегмента по
  256: R->G, G->B, B->R) и выставляет ШИМ на все три канала, с общей
  яркостью rainbowMaxBright.

void backlBrightTick()
  Главный тик подсветки. Порядок проверок: авария DC-DC (мигание
  красным, приоритет над всем) -> обычная логика по curMode/BACKL_MODE:
  "дыхание" для красного/синего/зелёного (общая с колебанием
  backlBrightCounter, floor = BACKL_MIN_BRIGHT), кроссфейд радуги
  (два канала одновременно, floor = 0), статичные цвета/градиент/
  отключено при смене режима (chBL).

void changeBright()
  Пересчёт яркости день/ночь (раз в час). Обновлён под все текущие
  режимы: сброс backlMaxBright[]/rainbowMaxBright, пересчёт интервала
  дыхания/радуги под новую яркость, мгновенное применение для
  статичных цветов и градиента.

--- DCDC.ino ---
void DCDCTick()
  Регулировка HV + защита в три состояния (см. раздел 5). Порядок:
  проверка перенапряжения (100 мс) -> если уже FAULT, выход ->
  проверка "высокий PWM + низкое HV" (5 сек, -> FAULT) -> проверка
  "просевшее, но не критичное HV" (2 сек, -> WARNING/сброс в NORMAL) ->
  обычная регулировка ШИМ по обратной связи.

--- selftest.ino ---
bool startupTestRequested()
  Проверка удержания кнопки "минус" при включении (с холостым первым
  чтением АЦП для устранения шума).
void testShowHalf(byte offset, int value)
  Вывод трёхзначного числа (0-999) в 3 разряда начиная с offset.
int readVccRawADC()
  Измерение Vcc платы через встроенный источник опорного напряжения
  1.1В (без отдельного аналогового входа) - прямая работа с ADMUX/
  ADCSRA.
void runStartupTest()
  Вся последовательность стартового теста (см. раздел 4).

--- buttonsSettings.ino ---
Обработчики кнопок "минус"/"плюс" в режиме SHTIME полностью
переписаны под новую логику режимов подсветки/эффектов (см. разделы
1, 6). Обработчик кнопки "сенсор" обёрнут в #if SENSOR_MODE != 3
(см. раздел 8). retToTime() дополнена сбросом isFreeze.

--- 2_loop.ino ---
Добавлена ветка forceDirectTime: одноразовый прямой возврат к
отображению времени (sendTime()) без запуска эффекта перелистывания
цифр - используется после показа номера режима подсветки/пресета/
позиции градиента.


================================================================
11. КАРТА АДРЕСОВ EEPROM (SAVE_PARAMS, 0_data.ino)
================================================================
  0 FLIPEFF   - выбранный эффект перелистывания цифр
  1 LIGHTEFF  - выбранный режим подсветки (BACKL_MODE)
  2 GLEFF     - "глюки" вкл/выкл (не используется, GLITCH_ENABLED=0)
  3 VSET      - не используется
  4 ALHOUR    - час будильника
  5 ALMIN     - минуты будильника
  6 ALIFSET   - будильник заведён/сброшен
  7 BLCOLOR   - текущий цвет (используется только внутри радуги)
  8 DOTEFF    - секундная точка вкл/выкл
 9-10 GRADPOS - позиция в градиенте (int, 2 байта)
 11 BLBREATH  - "дыхание" вкл/выкл (для красный/синий/зелёный)
 12 RBSPEED   - индекс скорости радуги (RAINBOW_TIME_PRESETS)
Датчик (SENSOR_MODE) в EEPROM не хранится - это константа времени
компиляции, а не пользовательская настройка.
